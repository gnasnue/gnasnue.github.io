세션 구성과 쓰기 범위

작업 루프와 완료 판정

모든 변경이 같은 순서를 탑니다. 사람은 변경마다 코드를 읽지 않고, 이 루프가 통과해야 하는 기준을 정합니다.

  1. 명세명세 없는 코드 변경은 받지 않습니다
    AI
  2. 실패하는 시험기대값 파일을 먼저 씁니다
    AI
  3. 코드자기 경로 안에서만 고칩니다
    AI
  4. 로컬 실행통과한 뒤에만 push합니다
    규칙
  5. 교차 검토Codex가 읽기 전용으로 봅니다
    AI
  6. CI 단계 관문필수 시험 목록과 대조합니다
    규칙

에이전트의 실패 유형과 가드레일

에이전트가 틀리는 방식을 먼저 적고, 유형마다 그것을 막는 도구를 붙였습니다.

실패 유형막는 장치강제하는 곳
검증 없이 완료 보고완료는 CI 단계 관문만 판정합니다. 작업별 결과를 커밋 SHA와 실행 ID로 묶어 필수 시험 목록과 대조합니다.tools/stage_gate.py
시험이나 검사 도구를 고쳐서 통과승인한 시험, CI 워크플로, 검사 도구의 SHA-256을 잠금 목록에 올립니다. 검사기는 base 브랜치 판으로 실행해, 바뀐 검사기가 자신을 통과시키지 못합니다.docs/spec/locks.yaml tools/lock_check.py
skip, xfail로 우회아직 없는 시험은 단계 파일의 '예정' 목록에만 둡니다. 필수 시험 ID가 건너뛰어지거나 실행되지 않으면 실패합니다.docs/spec/stages.yaml
금지한 동작이 구현에 섞임금지한 동작을 실제로 시도하고 거부를 기대하는 시험 12종을 둡니다. 저장을 거부해야 하는 항목은 API, ORM, raw SQL 세 경로로 확인합니다.core/tests/constitution/
두 세션이 같은 파일을 수정경로마다 작성 세션은 하나입니다. 하위 에이전트는 git worktree에서 일하고 병합은 코어 세션만 합니다.CLAUDE.md 작업 규칙
작성 모델의 자기 검토 맹점다른 회사 모델이 읽기 전용으로 검토합니다. 같은 판(revision)을 양쪽이 명시적으로 수용한 경우만 합의로 기록하고 원문을 보존합니다.docs/proposals/codex-reviews/
세션이 바뀌며 맥락 유실상태, 결정, 명세를 서로 다른 문서에 두고 문서 검사가 줄 상한과 형식을 확인합니다. 생성할 수 있는 문서는 손으로 쓰지 않습니다.tools/docs_lint.py
CI 비용 초과pre-push 훅이 근거 없는 push를 막고, 기록 문서만 바뀐 push는 CI를 돌리지 않습니다. 월 예산은 10달러입니다..git/hooks/pre-push

교차 검토가 실제로 잡은 것 2026.09.01 첫 검토

작성 모델의 자체 검토에는 없던 규칙 위반 3건을 Codex가 찾았고, 세 건 모두 사실로 확인했습니다. 그 뒤로 교차 검토를 루프에 넣었습니다.

  • 실제 회사명을 가리는 관문에 우회 경로가 있었습니다.
  • 개정 문안에 확정 상태가 없었습니다.
  • 발의 단계 법안에 걸어 둔 산출물 상한이 작동하지 않았습니다.
